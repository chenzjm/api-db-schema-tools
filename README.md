# 接口与数据库结构工具 v0.9.17

Schema Studio 用于维护接口字段和数据库字段。底层仍然是普通 Markdown、YAML Frontmatter 和 Wikilink；Fileclass 提供属性定义，Schema Tools 负责 JSON/DDL 导入、字段管理和精准引用。本仓库的接口字段属性名称统一使用中文，接口协议里的字段名、路径和类型保留原始写法。

默认目录：接口文档为 `5.api/`，数据库文档为 `7.db/`，接口字段为 `_data/api-fields/`，数据库字段为 `_data/db-columns/`，总览视图为 `_bases/`。

迁移兼容：插件仍可读取历史英文属性；新建、保存和重新导入接口字段时，会统一写入中文属性。`ApiField`、`DbColumn` 是插件识别用的技术类名，不是团队需要记忆的业务字段名称。

## v0.9.17：建表语句同步的一处真 bug（重建丢列上约束）

**现象**：字段表 → 建表语句 同步开着，只改某一列的「数据类型」，重建后该列上挂的
`constraint SYS_C0050515 check ("PRE_INSURE_ID" IS NOT NULL)` 整段消失 —— 相当于改个类型就把列的 CHECK 约束删了。

**根因**：Oracle dump 常把列级约束拆到后续缩进行（`scanCreateTable` 已把这些行并入该列的 `item.text`）。
但 `buildDdlFromColumns` 重生成该列时只吐一行 `renderColumnDef(...)`，续行约束没人接回去。

**修法**：新增 `columnConstraintTail(itemText)`，只认 `constraint / check / references / foreign key /
primary key / unique / not null / null / default / on delete|update / deferrable / initially / enable|disable`
开头的续行并逐字拼回；遇到不认识的写法就停（宁可不保留也不猜）。只作用于「需要重生成」的列，
原文逐字节复用的列不受影响，幂等基准不变。

同时修掉两处回归自身的缺陷（都在测试侧，非产品行为）：

- `ddl-regression` 场景 11 调 `buildDbAnalysis` 漏传第 3 个参数（按表切片后的原始 SQL），
  真实链路一定会传，漏传导致 `a.sql` 为空 → 新表文档的「建表语句」代码块是空的，断言长期失败；
  场景 11 另加了「先在内存里删掉 ACCOUNT_FILE_FLAG 残留」，让「全新表」前提不受 vault 漂移影响。
- `run-all-regressions.sh` 在指定 `SCHEMA_STUDIO_MAIN` 时误报「基线未取到」（基线其实是部署副本），
  且结尾绿灯文案把「环境性失败条数」写死成 2；改为按实际比对结果自适应输出。

回归：ddl-regression 82/0、ddl-sync 73/0（新增 5 条约束保留用例）、api-import 67/0、
api-module 57/0、grid-edit 37/0、xxl 26/0、v0722-parity 134/0，全套 476 条全绿。

## v0.9.12：与并行分支 v0.7.22 的功能对齐回归（新增 138 条对齐断言 + 8 处补齐/修正）

这一版不是新功能，而是**把「对端有的」逐条验到「本版本也有且可用」**：新增
`.workbuddy/v0722-parity-regression.js`，同时加载对端与本版本的 main.js，同一份输入比输出（双版本差分），
再跑端到端流程。过程中抓出 8 处真实差异，全部已修。

**1. DDL 导入按表切片（此前会把整份 SQL 写进每张表文档）**
导入一份多表 DDL 时，各表文档的「## 建表语句」只放**本表**的建表语句 + 该表的 `COMMENT ON` + 该表的
`CREATE [UNIQUE] INDEX`，`ORDER_ITEMS` 的内容不会跑到 `ORDERS` 里。切不出片段时退回整份文本，不写空代码块。

**2. DDL 导入会回写既有表文档的代码块**
重新导入一份改过的 DDL，表文档里的建表语句跟着替换（幂等，不越堆越多），并登记自写抑制 ——
否则反向同步开着时，会把文档里的旧 SQL 又推回字段表，等于白导。

**3. DDL 导入默认方言改为 Oracle**（Oracle 也排在下拉首位）。本库的 DDL 全部来自 Oracle 导出
（SQL*Plus 的 `/` 结束符），默认落在 MySQL 解析器上是个老坑。输入框示例同步改成 Oracle 风格。

**4. 两个导入页的状态互不污染**
从 JSON 页切到 DDL 页（或反过来）时，若拿到的是另一页的状态形状就重建默认值，不再报「无法确定导入目标」。

**5. 新建内部接口文档套仓库模板**
新增设置项「新建接口文档的模板（内部接口）」（默认 `api-接口文档-jiekou`，含幂等 / 分页排序 / 交易状态判断），
外部接口继续用 client 模板。同时修掉内置兜底里的死链 —— `![[ApiFields.base#…]]` 少了 `_bases/` 前缀，
而它会被复制进此后新建的每一份接口文档。接口文档定位补上「在文档目录内按名查找」，不再在根目录多出副本。

**6. 写入卫生：模板里没有的属性不落盘**
导入落盘时只写 Fileclass 定义过的属性 —— 不再往字段文件里写 `parent_path` / `shape` / `order` / 英文 `name`
这些模板里没有的键（本库 158 个字段文件一个都没有，写进去只会污染业务文档与 git diff）。
层级改由 `字段路径` 推导、`shape` 由 `数据类型` 反推 —— 与模板里写的「父子层级完全由路径本身表达，
不另设层级属性」一致。**与对端白名单净化的区别**：本版本只决定「我们写什么」，不删既有文件里已有的键，
所以不会像对端那样抹掉用户自建属性。

**7. 导入 Diff 不再把每个既有字段都标成「有变化」**
API 侧的比对键收敛为 `字段路径 / 数据类型 / 方向`。`parent_path`、`shape`、`name` 不落盘，留在比对集合里
就会出现「旧记录读不到值、新记录有值」的假差异 —— 实测每个既有字段都被标成「有变化」。

**8. 身份键空值守卫对齐（空值从既有值回填）**
解析不出「字段名 / 数据类型」时，用既有文件里的值回填。此前只把这些键删掉 —— 值同样是丢的，
而现在连「旧值 → 空」这种假差异也一并消除了。

顺带：未拖选区域时 `Ctrl/Cmd+C` 取当前焦点单元格（此前必须先拖一个 1×1 的区域）。

## v0.9.11：内部 / 外部接口模块 + 报文封套（自并行分支 v0.7.19 / v0.7.20 移植）

**模块区分**。本库 `5.api/` 与 `6.client/` 下有**同名**接口（两边都有「助贷放款申请接口」），字段记录靠文件名的
「内部接口- / 外部接口-」前缀区分，而接口文档名本身不带前缀。这一版把这个约定接进插件：

- 左侧列表按**模块 + 接口名**分组，同名接口不再混成一组、互相覆盖
- 接口名比较前先剥前缀，导入时不会把另一模块的字段整批误判为新增
- 导入页新增「接口模块」下拉：选外部接口时，字段文件名带前缀、新建文档落 `6.client` 并套 client 模板
- 模块归属优先看接口文档所在目录（最可靠），其次看字段文件名前缀；判断不出时不区分，老数据不受影响

**报文封套**。内部接口报文形如 `{ head: {公共报文头}, body: {业务字段} }`。导入页新增「业务根节点」（选内部接口
时默认填 `body`）与「忽略的顶层节点」（默认 `head`）：前者只取该节点、字段路径不带 `body.` 前缀；后者按名单丢弃
顶层节点。**只在「模块＝内部接口」且内容是 JSON 时生效**，两项留空则完全 no-op。`__schema` 里的显式 `payloadKey`
优先级最高，老用法完全不变。

新增设置：外部接口文档目录（`6.client`）、新建外部接口文档的模板（client 模板，`{{:填写提示}}` 原样保留给用户填）。

## v0.9.10：表格撤销 / 重做 / 剪切 / 全选（自并行分支 v0.7.13 移植）

字段网格的编辑现在可以反悔：**Ctrl/Cmd+Z 撤销、Ctrl/Cmd+Shift+Z 或 Ctrl+Y 重做**（80 步历史），覆盖单元格编辑、
Excel/WPS 区域粘贴、Ctrl/Cmd+X 剪切、Delete/Backspace 清空、布尔切换。另补 **Ctrl/Cmd+A 全选整个区域**。

一次操作作为一批记录，撤销按批回滚：清空 6 格再撤销，一步全部还原。只有值**真的变了**才进历史（「主键」本来
就是 false、清空后仍是 false，不算一次修改），值没变时不产生历史噪音。产生新修改后原来的重做链作废（与编辑器
一致的语义）。

编辑框内按 Ctrl/Cmd+Z 交给输入框自己撤销刚打的字，不动表格历史 —— 要撤销表格改动先 Esc 退出编辑。

## v0.9.9：XML 报文导入 + 导入原始报文回写示例（自并行分支 v0.7.11 / v0.7.20 移植）

接口导入页现在同时吃 **JSON 和 XML**：文件接受 `.xml`，内容以 `<` 开头也自动按 XML 解析。手写的一个小解析器
（Obsidian 沙箱里没有 DOMParser，也不为一个导入功能引第三方依赖），支持元素 / 属性 / 文本 / CDATA / 注释 /
处理指令 / 实体。

解析约定：根元素只作报文容器（结果从根的子元素开始）；属性写成 `@属性名`；同名重复元素自动识别为数组；
元素既有属性又有文本时文本记为 `_text`（不用 `#text`，避免与 Obsidian 链接锚点冲突）；`<__schema api="…"
direction="…"/>` 作为元信息不参与字段解析。**类型推断默认关闭**（XML 里一切都是字符串，`<code>0001</code>`
不该被读成 1），需要时在导入页打开。

导入时把**原始报文逐字节**写进接口文档「## 请求示例 / ## 响应示例」对应的占位代码块（JSON 格式化后写入，
XML 原样写入）。文档里没有该章节或代码块时**不新建章节**，只在命令行提示跳过。

## v0.9.7：字段表 ⇄ 表文档「## 建表语句」同步（自并行分支 v0.7.22 移植）

改 `_data/db-columns` 里列文件的属性，表文档「## 建表语句」里的 SQL 跟着更新。**开关**：设置 → Schema Tools
→ 「字段表属性变化实时更新建表语句」（**默认关闭**，建议先用命令在单张表上验证）。命令面板：「按字段表更新当前表的
建表语句」「同步全部字段表到各表的建表语句」。

| 改列文件的 | 建表语句的变化 |
|---|---|
| `数据类型` | 该列的类型改写 |
| `可为空` | 补 / 去 `not null` |
| `主键` | 表级主键约束的**列列表**（约束名与 `USING INDEX … ENABLE` 等子句原样保留） |
| `索引` = true 且无索引覆盖 | 追加 `create index IDX_…`（取消标记后这条会被回收，可逆） |
| `说明`（该列原本没有 COMMENT 时） | 追加 `comment on column …` |
| 新增 / 删除列文件 | 追加 / 移除列定义（连它的 `comment on column` 一起） |

### 三条设计要点（都为了"同步"不伤原文）

1. **补丁式重建，不是整段重写**。只在「数据类型 / 可为空 / 默认值」真的不同时才重新生成那一项，其余**逐字节复用原文**
   （含对齐空格、`USING INDEX` 存储子句、`CONSTRAINT "SYS_…" PRIMARY KEY` 的引号与约束名）。**源与产物本就一致时，
   重建结果逐字节等于原文** —— 这是可验证的幂等基准，由 `.workbuddy/ddl-sync-regression.js` 用真实库文件守护。
2. **注释只补不改**。本库里人工润色过的「说明」与 DDL 原始注释普遍不同，覆盖回去等于毁掉人工成果，
   所以只有"该列还没有 COMMENT 且说明非空"时才补一条。
3. **索引只补不改不删**；只有本插件按 `IDX_<表>_<列>` 规则命名的索引会被回收，人工写的索引一律不动。

### 安全闸与抑制

- **列文件不完整就跳过**：一次要删掉的列超过现有列数一半时，判定为"列文件只建了一部分"，只提示不落盘。
- **占位注释（`-- 待补充`）与空代码块不生成 DDL**，一律跳过。
- **「疑似删除」的列不参与重建**（标记来自 `_data/.schema-state.json`，删掉标记即可恢复该列）。
- **自写抑制**：同步写完表文档后登记这次写入的内容，供反向链路（P2）识别，两个方向都接上也不会来回抖。

## v0.9.0：新增 xxl-job 域（XML → 任务流 / 批任务 / 任务组件）

侧栏的域页签由「接口 / 数据库」扩为 **「接口 / 数据库 / xxl-job」**。第三个域用来把 xxl-job 平台导出的 XML
生成三级文档，遵守本插件的界面风格与运行机制（同一套 shell / header / 表格 / 设置页）。

### 1. 文档结构

导入输出在 `<文档根目录>/<执行器>/{任务流,任务,任务组件}`（默认根目录 `8.xxljob`）：

| 层级 | fileClass | 说明 |
|---|---|---|
| 任务流 | `任务流` | 链路入口，`jobLevelType = MAIN_TRIGGER_JOB` |
| 批任务 | `批任务` | 编排节点，`VIRTUAL_JOB` |
| 任务组件 | `任务组件` | 实际执行单元，`COMPONENT_JOB` |

- frontmatter 严格沿用模板的键顺序；能推断的填真实值，推断不了的**保留模板里的 `{{填写提示}}`**。
- 正文套用设置里的三份模板：占位简述与示例 mermaid 会被替换成真实内容，其余章节原样保留。
- **归属关系写在正文**：批任务有 `# 对应任务流`、任务组件有 `# 对应批任务`，内容是
  `[[8.xxljob/<执行器>/<层级>/<名称>|<名称>]]` 双链；章节排在 `# 任务说明` 之前。fileClass 里
  不再有 `对应任务流名称` / `对应批任务名称` 两个字段。
- 调度状态一律写「停止」；任务参数只在批任务 frontmatter，正文不展开。

### 2. 浏览与预览

浏览页按执行器分组展示三级文档，每份文档一张卡片：标题点击打开笔记，下方以**阅读模式**
预览「笔记属性」（frontmatter）——渲染后的属性列表，不再展示 YAML 源码，也不展示正文。

### 3. 导入流程

侧栏「+ 导入 xxl-job XML」→ 选 XML（可多选）→ 确认执行器（XML 里只有 `jobGroup` 编号，
靠设置里的执行器清单匹配，确认后自动回写）→ 查看导入清单（类型 / 文档 / 路径 / 目标状态 + 预览）→ 写入。

导入清单的预览同样是阅读模式。对已存在的文档，改动直接标在属性行里：
`旧值删除线 → 新值`（与数据库域的单元格 diff 同款观感，含删除线的行自动高亮）；
该文档的预览默认展开，summary 一行列出「属性改动 N 处：改动键名」。

改动判定按 **YAML 标量语义**比较，不是逐字比较：`'{"dayOffset":"-1"}'` 与
`"{\"dayOffset\":\"-1\"}"` 是同一份内容的两种引号写法，不算改动——
否则老文档（单引号写法）每次导入都会把「没动过的任务参数」报成改动。

「跳过」策略是**智能跳过**：已存在文档**有属性改动就按更新写入**（保留手写正文），
只有**完全无改动**才真的跳过——目标状态列因此显示「更新（N 处改动）」而不是一句「跳过」。

重名策略沿用本插件的三档：**跳过 / 更新（保留手写正文）/ 新建副本**。
「更新」= frontmatter 整体替换（废弃键自动清除）+ 归属章节刷新 + 其余手写正文原样保留。

### 4. 状态文件

来源信息（原任务 id、来源 XML、导入时间）写入 `<文档根目录>/.xxljob-state.json`，
与数据库域的 `_data/.schema-state.json` 分开，互不污染，也不写进业务文档正文。

### 5. 源码位置与构建

xxl-job 的实现**已搬进本仓库**，就在 `src/xxljob/`（TypeScript），不再从外部仓库拷 bundle：

| 路径 | 内容 |
|---|---|
| `src/xxljob/*.ts` | 解析 / 建树 / 模板渲染 / 写盘 / 执行器清单等（不含独立插件入口 `main.ts`） |
| `src/xxljob/ui/importModal.ts` | 四步导入向导（可选，Studio 自己也有内联导入页） |
| `tests/xxljob/` | 单元测试（16 条）+ 模板基线 `templates/xxljob/` |
| `scripts/` | `test.mjs` / `bundle-check.mjs` / `dryrun.*` |
| `xxljob-bundle.cjs` | **构建产物，不入库**；由 esbuild 从 `src/xxljob/bundle.ts` 产出 |

```bash
npm install          # 首次：装 esbuild / typescript / obsidian 类型
npm run build        # 类型检查 + 产出 xxljob-bundle.cjs
npm test             # 16 条单元测试 + bundle 冒烟
npm run dryrun -- <xml...> --write --templates=<模板目录>
```

`./sync.sh to-vault|deploy` 会**先构建再部署**，所以日常改完 `src/xxljob/` 直接跑 sync.sh 即可。

> ⚠️ 构建脚本只输出 `xxljob-bundle.cjs`，**绝不会覆盖根目录手工维护的 `main.js`**
> （本插件主体仍是手工 CJS，`tsconfig.json` 的 include 只涵盖 `src/xxljob/`）。

产物由 `require('./xxljob-bundle.cjs')` 加载，包在 try/catch 里：

```js
let xxl = null;
try { xxl = require('./xxljob-bundle.cjs'); } catch (e) { /* 降级：xxl-job 域不可用 */ }
```

**没构建 / 产物缺失时整个 xxl-job 域降级为不可用，接口 / 数据库两条链路不受影响。**

## v0.8.2：新建表文档按模板生成（含 schema 子目录与表注释）

新增表（DDL 导入新建、或在界面手工新建）时，表文档不再是一个最小空壳，而是套用可配置的模板。

### 1. 表文档模板

新增设置项 **「新建表文档的模板」**（`dbDocTemplate`，默认 `_template/业务模板/db-数据库-shuju/db-数据库-shuju.md`）。
生成时自动填充模板里的：

| 模板字段 | 取值 |
|---|---|
| `表名` | CREATE TABLE 的表名（自动去掉 schema 前缀与引号） |
| `数据库Schema` | DDL 里的 schema，如 `"CAPITAL"` → `capital` |
| `表中文名` | `COMMENT ON TABLE ... IS '...'` 的表注释 |
| `建表语句` 代码块 | DDL 原文 |

模板里其余的 `{{...}}` 填写提示原样保留，作为人工填写提醒。模板文件不存在时回退到内置的最小结构。

### 2. 新增表注释与 schema 解析

- 新增 `applyTableComments()`：解析 `COMMENT ON TABLE <schema.>?<table> IS '...'`（表中文名的来源）。
- `CREATE TABLE` 支持 schema 限定名 `"CAPITAL"."ACCOUNT_FILE_FLAG"`，解析后同时记录 schema。
- 全部为新建表时，表文档落到同名 schema 子目录（如 `7.db/capital/ACCOUNT_FILE_FLAG.md`），
  与多 Schema 的目录结构一致，不再丢在 `7.db/` 根目录。

### 3. 其他

- 数据类型归一补上逗号后的空格：`NUMBER(10,0)` → `NUMBER(10, 0)`。
- 新建的列文件正文「所属表」使用完整路径链接（`[[7.db/capital/X|X]]`），与既有文件一致。

## v0.8.1：导入不再因文件损坏而中断，类型解析不再混入约束尾巴

修复真实导入中暴露的三类问题。

### 1. 字段名被清空后导入会中断（已修）

`字段名` 缺失时，插件原本直接用**整个文件名**兜底（如 `CAPITAL_INSURANCE_PRE_APPLY__CERT_TYPE`），
与 DDL 里的列名 `CERT_TYPE` 匹配不上 → 该列被当成新字段 → 走新建分支撞上已存在的文件 →
抛错中断，整批导入无法应用。

- 新增 `memberNameFromFilename()`：从文件名还原字段名时剥掉「`<表名>__`」前缀（API 侧再剥「`<方向>__`」）
- 应用更新时增加**按文件路径兜底匹配**：名字匹配不上、但文件确实存在时改为更新它，不再新建
- 新增 `SCHEMA_GUARDED_KEYS`：`字段名` / `数据类型` / `字段路径` 在导入值缺失时**保留文件里已有的值**，绝不写空

### 2. 数据类型混入 constraint 尾巴（已修）

Oracle 导出的命名式 check 约束写在下一行：

```sql
CREATE_TIME DATE
    constraint SYS_C0050516
        check ("CREATE_TIME" IS NOT NULL),
```

列类型截断的关键字列表原先没有 `CONSTRAINT`，会把约束一起吃进类型
（解析出 `"DATE constraint SYS_C0050516"`）。现已补上，`CREATE_TIME` 正确解析为 `DATE`（且非空）。

### 3. 回归测试扩充

新增场景 8 / 9 / 10：字段名被清空仍能匹配回填、导入值缺失不写空、两种方言下类型都不含约束尾巴。

## v0.8.0：导入不再污染业务文档

这一版针对「字段定义只收录具有业务与设计语义的属性」做了改造：工具运行态元数据不再寄生在字段文档上，DDL / JSON 导入也不再按设置里的目录改写链接。

### 1. 运行态状态迁出 frontmatter

`来源方式` / `方言` / `疑似删除` / `最后导入时间`（`schema_source` / `schema_dialect` / `schema_orphaned` / `last_imported_at`）不再写入字段文档，改由中心化状态文件承载：

```
<字段记录目录的上级>/.schema-state.json      # 默认 _data/.schema-state.json
```

```json
{
  "version": 1,
  "updatedAt": "2026-10-15T00:00:00.000Z",
  "records": {
    "_data/db-columns/表名__列名.md": {
      "source": "ddl", "dialect": "oracle", "orphaned": false, "lastImportedAt": "..."
    }
  }
}
```

- 「疑似删除」改由状态文件判断，不再依赖文档里的 `疑似删除` 属性，也不会被人手误改影响判断。
- 状态文件可随 git 追踪，团队共享同一份 diff 状态。若不想入库，加进 `.gitignore` 即可。

### 2. 废弃属性不再写入

`引用`（`references`）、`顺序`（`order`）已从字段定义移除，导入与新建都不再写入；发现历史遗留的 `引用` / `顺序` / `schema_*` / `ddl_comment` 等键时，会在**下一次导入时顺带清理掉**。

### 3. DDL 列注释并入「说明」

DDL 的 `COMMENT ON COLUMN` 不再单独存 `ddl_comment`，而是并入 `说明`：

- **已有非空 `说明` 的列不会被覆盖**（人工润色的文案优先）；
- 只有 `说明` 为空 / 空白时才用 DDL 注释补齐。

### 4. 表 / 接口文档链接不再被改写

导入时优先沿用**现有字段记录已指向且确实存在**的表文档 / 接口文档位置；只有全新对象才落到设置里的文档目录。这样多 Schema 分子目录的知识库（如 `7.db/capital/`、`5.api/助贷/`）不会再被按扁平目录改写链接、也不会在目录根部多出一份空文档。

### 5. 修复：中文键知识库下导入无法应用

`applyDdl` / `applyOneApiAnalysis` 与两个 Diff 表格此前用 `r.name` / `r.path` 取值，而中文键知识库里这些值存在 `字段名` / `字段路径` 上，取到的是 `undefined`，导致：

- 「分析全部并查看 Diff」只有一行、且行键是 `undefined`；
- 「应用全部更新」对每一列都走「新建文件」分支，实际会先写一个 `<表名>__field.md` 然后报错中断。

现在统一以规范字段名（`key`）作为行标识，并让表格读值走同一套中英别名解析，Diff 也不会再出现「值 → 空」的假差异。

### 6. 其他

- Diff 表格不再为中英双份属性各显示一列。
- 体验样例生成器不再写入 `已复核` / `顺序` / `疑似删除` / `引用`。

## 仓库与部署

本仓库是插件本体（`main.js` 构建产物）的版本库，不含任何知识库业务数据。

| 文件 | 说明 |
|---|---|
| `main.js` | 插件构建产物，Obsidian 实际加载的文件 |
| `manifest.json` | 插件清单（id / 版本 / 最低 Obsidian 版本） |
| `styles.css` | 插件样式 |
| `versions.json` | 版本兼容表 |
| `data.json` | **不入库**：本机运行态配置（目录、网格视图偏好），已在 `.gitignore` |

### 同步脚本

插件仓库与 Obsidian vault 的部署目录之间用 `sync.sh` 同步：

```bash
./sync.sh to-vault                 # 仓库 → vault：把改好的插件部署到 Obsidian
./sync.sh from-vault               # vault → 仓库：把 vault 里现场改的文件收回仓库
./sync.sh deploy "改了什么"         # 一条命令：部署到 vault + git commit + git push
```

`deploy` 是最常用的：改完代码执行它，脚本会列出本次改动、部署到 vault、提交并推送，
最后提示去 Obsidian 重载插件。若仓库无改动或远端已是最新，会跳过对应步骤。

默认目标目录是本机 vault 路径，可用 `VAULT_DIR=/别的/路径 ./sync.sh to-vault` 覆盖。

### 改完之后如何生效

`main.js` 是 Obsidian 直接加载的文件，没有编译步骤。部署后需要在 Obsidian 里重载：

- **只改逻辑**：设置 → 第三方插件 → 关闭再打开本插件（约 1 秒）
- **改了 `styles.css`**：`Ctrl/Cmd+P` → `Reload app without saving`（整库重载，样式才一定刷新）

如果 vault 里装了 **Hot Reload** 插件（pjeby），上面两步都可以省掉：

- Hot Reload 只监听「目录里有 `.git` 或 `.hotreload` 标记」的插件，所以本插件的部署目录里需要 `.hotreload` 文件
- `./sync.sh to-vault` 和 `./sync.sh deploy` 每次都会自动重建这个标记，无需手工维护
- 标记存在且 Hot Reload 已启用时，部署一写文件就会自动重载插件，并在 Obsidian 里弹出提示

`main.js` 是 Obsidian 直接加载的构建产物，没有编译步骤；改完执行部署后重载插件即可生效。
